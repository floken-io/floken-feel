floken-feel · 网页端 FEEL 实时错误提示

原生 ES Module 直接加载 dist/editor.js（diagnose + highlight）， 零打包器、零 Node 依赖。边打字边出：语法着色 + 波浪线 + 错误码 + 定位 + "可能漏了什么"。

表达式（打开就有树；点下面的示例按钮可切换场景）

着色走 highlight(src)；波浪线走 diagnose(src)。 两者**共用同一套名字合并规则**，所以着色边界 === 解析边界（不会出现"划错位置"）。 免费送的：1 + 这种"末尾少东西"是零宽诊断（start === end），画成一个红色竖标记。

    求值（主入口 evaluate：运行期诊断 —— 未知变量 / 类型不符，默认给 null + 诊断，不抛）

    可用变量：{"tags": ["vip","new"], "name": "Ada", "age": 30} 
    （点上面的按钮）

    解析树（AST）—— 红/橙节点就是"错在这"的那棵子树

    parseWithDiagnostics(src) 给 AST；诊断区间与节点区间求**包含**（不是相交）， **最小的那个包含节点**才是出错点，只有它挂诊断码 —— 所以 list contains(tags,"vip") + 1 会标在 binary 那层，而不是把整条路径染红。
    · 红 = 语法诊断；橙 = 运行期诊断（点上面"求值"后出现，鼠标停在 tag 上看 message）。
    · 点节点 → 在编辑器里**选中它对应的源码区间**（想看"错在哪几个字符"就用这个）；点左侧 ▾ 折叠子树。
    · ⚠️ 已知粒度限制：**运行期诊断**覆盖的是**整个出错节点**（如整个 call），不细到实参（例： substring(age,2) 报的是整段 call，不是 age 那一个实参）。语法诊断（红）精确到 token。
    · 语法没走完时建不出树（ast 为 null），此时退化成**按括号分组的词法树**（示例 ②③）—— 它也是树，但只有括号层级，没有语法结构。
